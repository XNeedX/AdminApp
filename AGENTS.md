# Инструкции для AI-Агента (AdminApp)

## Контекст проекта и пути
- **Рабочая область:** Локальный полирепозиторий (`E:\Innowise Project\`).
- **Backend (`Backend/`):** Микросервисы на ASP.NET Web API.
- **Frontend (`Frontend/AdminApp/`):** Админ-панель на Angular (текущий фокус).
- **Frontend (`Frontend/ClientApp/`):** Клиентское приложение.

Твоя задача — генерировать, рефакторить и анализировать код исключительно для **`Frontend/AdminApp/`**. Не пытайся изменять или анализировать файлы бэкенда без прямого запроса.

## Архитектура и структура директорий
Соблюдай современную модульную структуру внутри `Frontend/AdminApp/src/app/`:
- **`core/`**: Синглтон-сервисы, HTTP-интерцепторы (interceptors), guard'ы, базовые конфигурации, логика аутентификации.
- **`shared/`**: Переиспользуемые presentational-компоненты (UI-элементы), пайпы (pipes), директивы.
- **`features/`**: Бизнес-логика, сгруппированная по доменам (например, `users/`, `dashboard/`, `settings/`). Каждый feature-модуль должен иметь свой роутинг и быть максимально независимым от других фич.
- **`api/`**: Сгенерированные клиенты и сервисы для работы с Backend API.

## Правила создания Angular-компонентов
- **Standalone API:** Используй `standalone: true` для всех новых компонентов, пайпов и директив. Не используй `NgModule`, если это не требуется для интеграции специфичных legacy-библиотек.
- **Паттерн Smart/Dumb:** 
  - *Smart (Container) Components:* Отвечают за инъекцию сервисов, вызов API, управление состоянием. Передают данные вниз через `@Input()`.
  - *Dumb (Presentational) Components:* Отвечают только за UI. Не содержат бизнес-логики и привязки к сервисам. Сообщают о действиях пользователя родительскому компоненту исключительно через `@Output()`.
- **Производительность:** По умолчанию устанавливай `changeDetection: ChangeDetectionStrategy.OnPush` для всех новых компонентов.
- **Жизненный цикл:** Избегай сложной логики в `constructor`, используй `ngOnInit`. 

## Управление состоянием и Реактивность
- **Signals:** Максимально используй Signals (`signal`, `computed`, `effect`, `input`, `output`) для локального состояния компонентов и связывания данных в шаблонах.
- **RxJS:** Используй `Observable` для асинхронных операций (HTTP-запросы, роутинг, глобальные события).
- **Интеграция:** Преобразуй потоки RxJS в Signals в компонентах с помощью `toSignal()` для удобного рендеринга без `AsyncPipe`.
- **Утечки памяти:** Никогда не оставляй "висящие" подписки. Если ручная подписка (`.subscribe()`) необходима, обязательно используй инъекцию `DestroyRef` и оператор `takeUntilDestroyed()`.

## Взаимодействие с Backend API (ASP.NET & OpenAPI)
- **Генерация кода:** В проекте применяется автогенерация API-клиентов из Swagger/OpenAPI спецификаций ASP.NET.
- **Запрет на ручной код:** **НЕ пиши** вручную TypeScript-модели, DTO или Angular HTTP-сервисы для взаимодействия с API. 
- **Порядок действий:** Если для выполнения задачи нужен новый эндпоинт, используй существующие сгенерированные сервисы. Если нужных методов нет, скажи: *"Необходимо обновить сгенерированный API-клиент из актуального swagger.json микросервиса"* и дождись моих инструкций.
- **Обработка ошибок:** Выноси логику обработки глобальных API-ошибок (401, 403, 500) в функциональные HTTP Interceptors (`HttpInterceptorFn`).

## Стилизация и UI (Tailwind CSS)
- **Утилитарный подход:** Используй классы Tailwind CSS напрямую в HTML-шаблонах (`class="flex items-center p-4 bg-gray-50"`).
- **Инкапсуляция стилей:** Минимизируй использование `.scss` файлов компонентов. Не используй директиву `@apply` для создания кастомных классов, если стили можно вынести в переиспользуемый Angular-компонент (например, отдельный компонент `<app-button>`).
- **Адаптивность (Responsive):** Обязательно используй брейкпоинты Tailwind (`sm:`, `md:`, `lg:`, `xl:`) для построения адаптивного интерфейса Mobile-First.
- **UI-библиотеки:** Комбинируй классы Tailwind с доступным Headless UI (например, Angular CDK) для создания сложных интерактивн1ых элементов (модальные окна, дропдауны, оверлеи).

## Типизация и TypeScript
- **Строгий режим:** Категорически запрещено использование типа `any`. 
- **Type Guards:** Если тип данных из внешней среды неизвестен, используй `unknown` и пиши функции-валидаторы (Type Guards).
- **Именование:** Названия интерфейсов и типов не должны начинаться с префикса `I` (правильно: `User`, неправильно: `IUser`), классы пишутся в `PascalCase`, переменные и методы в `camelCase`.
